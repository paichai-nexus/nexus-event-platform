# Development Plan

## 1. 개발 목표

제24회 배재대학교 경영대학 학술제에서 입장 확인, 청중평가, 심사위원 평가, 점수 집계, 경품 추첨과 결과 정리를 하나의 모바일 웹 기반 운영 흐름으로 연결한다.

별도 앱 설치 없이 사용할 수 있어야 하며, 행사장 네트워크 지연과 기기 문제를 고려해 핵심 입력 과정은 짧고 단순하게 설계한다.

## 2. MVP 범위

### 반드시 구현

- 행사·발표팀·평가항목 등록
- 참가자 QR 입장 확인
- 중복 입장 방지와 입장 시각 기록
- 입장 인증자 대상 팀별 1인 1회 청중평가
- 심사위원 전용 평가 입력
- 전문 심사 80%와 청중평가 20% 환산
- 입장·투표·심사 제출 현황 대시보드
- 참석자 대상 경품 추첨과 당첨 이력
- 참석·투표·심사·최종 결과 내보내기
- 리허설 데이터와 본행사 데이터 분리

### 이번 버전에서 제외

- 위치 센서 기반 참가자 추적
- 개인별 체류시간 분석
- 군중흐름 AI 예측
- AI에 의한 자동 탈락 또는 감점
- 범용 행사 SaaS 수준의 다기관 결제·과금 기능

체류시간 기반 에이전트 시뮬레이션은 별도 연구 저장소에서 검증한 뒤, 운영 시스템과의 연동 필요성이 확인될 때 후속 과제로 다룬다.

## 3. 사용자와 권한

| 사용자 | 주요 기능 | 접근 제한 |
| --- | --- | --- |
| 참가 학생 | QR 입장, 일정 확인, 청중평가 | 본인 입장·평가 기록만 처리 |
| 심사위원 | 평가 항목 입력, 제출 상태 확인 | 배정된 분야와 발표팀만 접근 |

| 시스템 관리자 | 행사 설정, 계정·데이터 관리, 장애 대응 | 최소 인원에게만 권한 부여 |

## 4. 권장 기술 기준

기술 스택은 첫 개발회의에서 확정한다. 아래 조합은 짧은 일정, 모바일 웹, 실시간 현황과 배포 편의성을 기준으로 한 초기안이다.

| 영역 | 초기 권장안 | 선택 이유 |
| --- | --- | --- |
| Frontend | Next.js + TypeScript | 모바일 웹과 관리자 화면을 한 프로젝트에서 운영 가능 |
| UI | Tailwind CSS | 짧은 일정에 일관된 반응형 화면 구현 |
| Backend / DB | Supabase PostgreSQL | 인증, DB, 권한 정책과 실시간 조회를 빠르게 구성 |
| Validation | Zod | 평가값과 관리자 입력의 형식 검증 |
| QR | 브라우저 기반 QR 라이브러리 | 별도 앱 없이 카메라 또는 링크로 입장 처리 |
| Export | CSV/XLSX | 행사 종료 후 학교 행정자료로 활용 |
| Test | Vitest + Playwright | 계산 로직과 실제 사용자 흐름 검증 |
| Deploy | Vercel + Supabase | 미리보기 배포와 행사 전 버전 고정 용이 |

## 5. 핵심 데이터 모델

- Event: 행사 정보와 운영 상태
- User: 참가자, 심사위원, 행사 담당자
- Team: 본선 발표팀과 참가 분야
- CheckIn: 입장 여부와 입장 시각
- EvaluationCriterion: 평가 항목, 배점과 가중치
- AudienceVote: 청중평가 제출 기록
- JudgeScore: 심사위원 평가와 제출 상태
- ScoreRule: 환산 비율, 가산점과 동점 처리 규칙
- PrizeDraw: 추첨 조건과 당첨 이력
- AuditLog: 관리자 변경과 주요 처리 기록

## 8. 완료 기준

기능은 화면이 보이는 것만으로 완료 처리하지 않는다. 다음 조건을 모두 만족해야 한다.

- 요구사항과 예외 상황이 Issue에 기록되어 있음
- 정상 흐름과 실패 흐름이 모두 테스트됨
- 권한이 없는 사용자의 접근이 차단됨
- 개인정보가 화면·로그·내보내기 파일에 불필요하게 노출되지 않음
- 다른 팀원이 실행할 수 있도록 문서가 작성됨
- Pull Request 리뷰와 승인 완료
