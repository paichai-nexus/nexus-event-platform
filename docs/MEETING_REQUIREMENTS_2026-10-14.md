## 평가 운영 기준

- 확인됨: 전문심사 80%, 청중평가 20%, 관리자/스태프의 투표 상태 제어, DB 점수 범위 검사, 팀별 중복 제출 제약, 서버 추첨과 감사 기록.
- 일부 구현: 체크인 기반 참가 자격, 제출 이후 읽기 전용, 평가 시작·종료. 화면과 DB 일부에만 존재하며 하나의 서버 제출 흐름으로 아직 연결되지 않았다.
- 결정 대기: 전문심사 기준별 가중 평균, 청중평가 환산, 무효표 사유별 처리, 동점 우선순위, 자동 평가 시간, 결과 확정 승인자.

위 결정이 완료되기 전까지 운영 화면은 최종 결과 확정을 허용하지 않는다.

## 데이터 무결성 위험

1. `SERVER MOCK` 데이터는 프로세스 메모리이므로 재시작 시 사라진다.
2. 현재 Supabase 미설정 환경에서는 관리자 인증이 우회되는 개발 모드다.
3. 기존 구조는 같은 행사 행의 `mode`만 변경하므로 리허설과 LIVE 데이터가 섞일 수 있었다. 이번 변경은 직접 전환을 차단하지만, 별도 LIVE 행사 생성 기능은 추가로 필요하다.
4. 공개 투표는 아직 브라우저 로컬 Mock이다. 공식 청중평가 데이터로 사용하면 안 된다.
5. 준비된 SQL 파일(`007`~`010`)은 검토용이며 운영 DB에는 적용하지 않았다.
6. 경품 공개 애니메이션은 서버가 반환한 당첨자를 받은 뒤 시작한다. 화면 속 빠른 번호는 연출 전용이며 당첨 결과를 다시 선택하지 않는다.
