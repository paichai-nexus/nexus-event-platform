# 경품 추첨 기능 설계

## 1. 목적

체크인을 완료한 행사 참가자를 대상으로 경품을 추첨하고,
당첨 결과와 추첨 이력을 확인할 수 있도록 한다.

현재 문서는 공식 행사 시스템에 통합하기 전,
개인 프로토타입에서 경품 추첨의 핵심 동작을 검증하기 위한 설계이다.

## 2. 추첨 대상

추첨 후보는 다음 두 조건을 모두 만족해야 한다.

- 체크인을 완료한 참가자
- 이전 추첨에서 당첨되지 않은 참가자

따라서 체크인하지 않은 참가자와 이미 당첨된 참가자는
추첨 후보에서 제외한다.

## 3. 추첨 과정

```text
참가자 목록
    ↓
체크인 여부 확인
    ↓
기존 당첨자 제외
    ↓
추첨 후보 확인
    ↓
후보 중 1명 무작위 선택
    ↓
당첨자 표시
    ↓
추첨 이력에 기록
```

## 4. 중복 당첨 방지

추첨 전에 기존 추첨 이력에 포함된 참가자의 ID를 확인한다.

이미 당첨된 참가자는 추첨 후보에서 제외하여
한 명의 참가자가 여러 번 당첨되는 것을 방지한다.

## 5. 추첨 가능한 참가자가 없는 경우

추첨 후보가 한 명도 없으면 당첨자를 선택하지 않는다.

UI에서는 추첨 버튼을 비활성화하여
추첨을 진행할 수 없도록 한다.

## 6. 추첨 이력

추첨이 완료되면 다음 정보를 기록한다.

- 참가자 ID
- 표시 이름
- 추첨 시간

현재 프로토타입에서는 추첨 이력을 브라우저 상태로 관리한다.

따라서 페이지를 새로고침하면 추첨 이력이 초기화된다.

## 7. 테스트 데이터 및 개인정보

현재 프로토타입에서는 실제 행사 참가자의 개인정보를 사용하지 않는다.

테스트 참가자는 `test-01`, `test-02`와 같은 테스트 ID를 사용한다.

## 8. 공식 시스템 통합 시 고려사항

현재 프로토타입은 브라우저에서 동작하는 검증용 기능이다.

공식 행사 시스템에 통합할 때에는 다음 기능을
서버 및 데이터베이스 기준으로 구현해야 한다.

- 행사 운영자만 추첨할 수 있도록 권한 검증
- 서버/DB에서 중복 당첨 방지
- 추첨 이력 영구 저장
- 공식 참가자 및 체크인 데이터와 연결

현재 프로토타입의 브라우저 상태만으로 실제 행사 운영을
처리하는 것은 범위에 포함하지 않는다.

## 9. 검증 방법

Vitest를 사용하여 다음 항목을 검증한다.

- 체크인한 참가자만 추첨 후보가 되는지
- 이미 당첨된 참가자가 다시 후보가 되지 않는지
- 추첨 후보가 없을 때 당첨자가 반환되지 않는지
- 후보 중 한 명이 선택되는지

실행 명령:

```bash
npm test
```

## 10. 범위

현재 프로토타입에서는 경품 추첨의 핵심 동작 검증에 집중한다.

기존 행사 규칙이나 점수 계산 방식은 변경하지 않는다.
