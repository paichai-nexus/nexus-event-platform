## 운영 원칙

이 프로젝트는 직급보다 담당 결과물을 기준으로 운영한다. 각 기능은 담당자 1명을 명확히 지정하고, 담당자는 Issue와 Pull Request를 통해 진행 상황을 기록한다.

현재 명단은 프로젝트 착수를 위한 초기 책임 구조다. 실제 코딩 담당은 첫 개발회의에서 개인의 기술 수준과 참여 가능 시간을 확인한 뒤 Issue 단위로 확정한다.

## 의사결정 방식

1. 행사 규정과 평가 기준은 경영대학의 최종 승인을 따른다.
2. 기술 구현 방식은 Development Lead가 검토하고 Project Lead가 확정한다.
3. 개인정보, 평가 공정성 또는 결과 변경과 관련된 사항은 Internal Review 검토를 거친다.
4. 기능 변경은 구두 지시로만 처리하지 않고 GitHub Issue에 근거를 남긴다.
5. 본행사 배포는 리허설 결과를 확인한 뒤 Project Lead가 승인한다.

## 추가 개발 참여자 배정 기준

- 참여 가능 시간과 마감 준수 가능 여부
- 맡으려는 기능과 현재 기술 수준
- Git·GitHub 기본 규칙 준수 여부
- 작은 Issue부터 끝까지 완료한 기록
- 행사 당일 또는 사전 리허설 참여 가능 여부

단순히 이름만 개발팀에 올리지 않는다. 구현, 테스트, 문서화 또는 현장 운영 중 하나 이상의 결과물을 책임질 수 있을 때 담당자로 배정한다.
